Write Amplification — Short Notes

Write Amplification: 
    Physical data written to disk is much larger than the actual logical data changed.
    
    In our `SimpleDB`:
        Update 1 key → serialize entire object → rewrite entire file
            Example:
                DB size = 100 GB
                Change = 10 bytes
                Physical write ≈ 100 GB
                    WA = Physical Write / Logical Write
                    High write amplification → more disk I/O, slower writes, higher SSD/HDD wear.
                    `truncate()` + full `write()` causes the entire file to be rewritten.
                    Production DBs reduce this using:

                    WAL (Write-Ahead Log)
                    B-Tree / page-level updates
                    LSM Tree
                    Compaction
                    Read from `hash` is approximately O(1), but loading the entire DB initially is O(file size).
